Quickstart & Installation

Production setup guide for deploying Swarm AI on macOS, Windows, and Linux workstations with local PTY bridges.

1. Prerequisites & Runtime Requirements

Before launching Swarm AI, ensure your host operating system meets the following baseline toolchains:

# Check Node.js and Git installations node -v # Must be v20.0.0 or higher git --version # Git 2.38.0+ required for worktree concurrency pnpm -v # Recommended package manager (v9.0.0+)

2. Operating System Specific Installation

macOS (Apple Silicon & Intel):

1. Download SwarmAI.dmg from the distribution grid.
2. Open the disk image and drag SwarmAI.app into /Applications.
3. If Gatekeeper displays an unsigned developer warning on first launch, execute the quarantine bypass:

xattr -d com.apple.quarantine /Applications/SwarmAI.app

Windows 10 / 11 (64-Bit):

1. Run SwarmAI_Setup.exe and proceed through the NSIS installer wizard.
2. Ensure PowerShell execution policy permits local scripting for PTY spawning:

Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned

Linux (Ubuntu / Debian / Fedora):

# For AppImage: chmod +x SwarmAI.AppImage ./SwarmAI.AppImage --no-sandbox # For Debian / Ubuntu (.deb): sudo dpkg -i SwarmAI.deb sudo apt-get install -f

3. Workspace Initialization & Hive Bootstrapping

When you select a project directory in Swarm AI, the core engine automatically executes the following non-destructive initialization steps:

1. Memory Directory: Creates a local .pheromone/ folder containing an embedded SQLite database (memory.db).
2. Worktree Cache: Sets up .swarm/worktrees/ for managing ephemeral branches and automatically appends it to .gitignore.
3. CLI Discovery: Scans your user $PATH for global binary installations of claude, codex, opencode, aider, and antigravity.
4. PTY Multiplexer: Allocates hardware-accelerated pseudo-terminal pipes with xterm.js frontends.

Pheromone Shared Memory Engine & Vector Schema

Technical specifications for local vector indexing, semantic search, and inter-agent memory synchronization.

1. Memory Architecture Overview

Traditional multi-agent systems suffer from context drift: Agent A invents an API endpoint, while Agent B writes frontend code calling a completely different URL. Pheromone eliminates this by maintaining an embedded SQLite database inside .pheromone/memory.db with sub-millisecond semantic search.

2. Database Schema & Tables

-- Core memory entities table CREATE TABLE IF NOT EXISTS memories ( id TEXT PRIMARY KEY, project_id TEXT NOT NULL, category TEXT NOT NULL CHECK(category IN ('architecture', 'decision', 'rule', 'plan', 'fact')), title TEXT NOT NULL, content TEXT NOT NULL, embedding BLOB, -- 384-dimensional cosine vector source_agent TEXT NOT NULL, -- e.g. 'claude-code-lead' confidence REAL DEFAULT 1.0, created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP, updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ); -- Synapse wire links table CREATE TABLE IF NOT EXISTS synapses ( id TEXT PRIMARY KEY, from_agent_id TEXT NOT NULL, to_agent_id TEXT NOT NULL, topic TEXT NOT NULL, weight REAL DEFAULT 1.0, last_synced TIMESTAMP DEFAULT CURRENT_TIMESTAMP );

Git Worktree Isolation & 3-Way Merge Engine

Deterministic file isolation mechanics, branch locking algorithms, and clean 3-way fast-forward merges.

1. The Problem of File Contention

When multiple autonomous agents operate inside the same working tree, concurrent disk writes cause catastrophic race conditions: partial AST writes, broken build states, and corrupted files.

2. Ephemeral Worktree Diagrammatic Lifecycle

Each parallel task follows a deterministic 6-stage lifecycle, ensuring complete file isolation and safe atomic integration into your primary codebase:

Stage 01 · Provisioning git worktree add
Isolated Worktree Spawn
Creates .swarm/worktrees/task-auth-01 on branch swarm/task-auth-01 branched from main.
git worktree add -b swarm/task-auth-01 .swarm/worktrees/task-auth-01 main
Stage 02 · Lock Registry .swarm/locks.json
File Ownership Declaration
Lead registers write-locks for src/auth/** and grants read-only access to sibling workers.
{ "task_id": "auth-01", "write_paths": ["src/auth/**"], "read_only": true }
Stage 03 · Execution Autonomous PTY
Parallel Worker Generation
Claude Code / Codex edits files in its isolated worktree without touching other workers' active buffers.
cd .swarm/worktrees/task-auth-01 && claude --model claude-opus-5
Stage 04 · Validation git merge-tree
3-Way Dry-Run Conflict Check
Performs in-memory 3-way merge validation across all completed worker branches before modifying git tree.
git merge-tree --write-tree main swarm/task-auth-01 swarm/task-ui-02
Stage 05 · Integration Fast-Forward
Atomic Fast-Forward Merge
Integrates validated feature branches directly into primary main branch with zero merge commits.
git checkout main && git merge swarm/task-auth-01 --ff-only
Stage 06 · Cleanup git worktree remove
Ephemeral Worktree Pruning
Automatically unmounts ephemeral folders and deletes temporary task branches to maintain clean disk state.
git worktree remove --force .swarm/worktrees/task-auth-01

3. File Ownership Safety Locks

During task decomposition, the Lead Steward creates a file lock table stored in .swarm/locks.json. If Agent 1 is assigned src/auth/*, Agent 2 is restricted to read-only access for those paths, guaranteeing mathematically zero merge conflicts.

Flow Canvas, Sockets & Live Telemetry Engine

Spatial execution graph, bidirectional socket wiring, and real-time token cost computation.

1. Spatial Graph Coordinates & Sockets

The Flow Canvas represents agents as reactive nodes in an infinite 2D plane with zoom capabilities (0.2x to 2.5x). Each node exposes 4 directional sockets:

• Top Socket: Upstream control signals & supervisory directives from Lead Steward.
• Bottom Socket: Downstream task delegation & worker dispatch.
• Left Socket: Inbound memory contracts & context inputs.
• Right Socket: Outbound API contracts & data pipelines.

Security, Sandboxing & Air-Gap Compliance

Zero-telemetry architecture, local credential security, and enterprise compliance standards.

1. Zero Cloud Proxy Guarantee

Swarm AI maintains zero middleman cloud infrastructure. When your agents call Anthropic, OpenAI, or a local Ollama instance, the HTTP/WebSocket connection originates directly from your localhost machine to the model provider. Your code, diffs, API keys, and repository files are never uploaded to any Swarm AI servers.

2. Operating System Keychain Vault

All API keys are encrypted at rest using OS-native security primitives:

• macOS: Apple Keychain via Security.framework.
• Windows: Windows Credential Manager (DPAPI).
• Linux: Secret Service API via libsecret / GNOME Keyring.

3. Sensitive Secret Scrubbing

Swarm AI's PTY stream filter automatically detects and masks environment secrets, JWT tokens, private keys (-----BEGIN RSA PRIVATE KEY-----), and .env variables before rendering them in the terminal buffer or passing them to vector memory.
